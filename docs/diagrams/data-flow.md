## Data flow description

1. **Input**: User supplies a manifest file (e.g., `requirements.txt`).
2. **Parser (W1)**: Parses the manifest into `DependencyNode` objects with `edge_availability = "unavailable"` (inventory-only).
3. **Graph IR**: Nodes are collected into a `DependencyGraph` with topology metadata.
4. **Engine (W2)**: NVD/OSV enrichment fallback enriches nodes with real CVE data. PHEI analyzer computes path-max risk scores on the graph.
5. **Reporter (W3)**: Generates a `RiskReport` (inventory report schema with evidence-grounded suggestions).
6. **Dashboard (W4)**: Stdlib `src.web` dashboard renders the report; Flask+D3 is an optional enhancement.
7. **AI (W5)**: Per-finding explanations are generated by the configured model (opt-in, defaults OFF) or deterministic fallback.
8. **Docker (W6)**: The entire stack is packaged into a portable multi-stage image (optional).

## Key constraints

- **No fabricated edges**: `edge_availability = "unavailable"` when topology is unknown.
- **No fabricated CVEs**: All findings come from OSV-Scanner.
- **No fabricated risk scores**: PHEI requires real topology.
- **Model defaults OFF**: `--model ON` required for AI explanations.
- **Flask+D3 optional**: stdlib `src.web` dashboard is the default; Flask+D3 is an enhancement.
- **Docker optional**: manual install via `requirements.txt` is sufficient for the demo.

## Notes

- Flask+D3 is optional — the stdlib `src.web` dashboard is sufficient for the December demo.
- Docker packaging is optional — manual install via `requirements.txt` is sufficient.
- No data flows to/from external model training (out of scope).
